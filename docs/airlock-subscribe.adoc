include::util/man-attributes.adoc[]
// tag::purpose[]
:manpurpose: Subscribe to Airlock events and receive notifications via socket

// =========================================================== Synopsis
== Synopsis
[verse]
// tag::synopsis[]
airlock subscribe [-h|--help] [--all] [--no-send-initial] [<event>...]

// end::synopsis[]

// =========================================================== Description
== Description

// tag::body[]
{manpurpose}

This command connects to the Airlock server and receives real-time event notifications as JSON lines.
The connection remains open until terminated (e.g., via Ctrl+C).

On connect, the current state is sent immediately (focus-changed with current window/workspace, mode-changed with current mode, etc.).

// =========================================================== Options
include::util/conditional-options-header.adoc[]

-h, --help:: Print help

--all:: Subscribe to all event types

--no-send-initial:: Do not send the initial state on connect

// =========================================================== Arguments
include::./util/conditional-arguments-header.adoc[]

The following events can be subscribed to:

focus-changed:: Fired when window focus changes. Includes `windowId`, `workspace`, `trigger`.

focused-monitor-changed:: Fired when the focused monitor changes. Includes `workspace`, `monitorId`, `trigger`.

focused-workspace-changed:: Fired when the focused workspace changes. Includes `workspace`, `prevWorkspace`, `trigger`.

mode-changed:: Fired when the binding mode changes. Includes `mode`.

window-detected:: Fired when a new window is detected. Includes `windowId`, `workspace`, `appBundleId`, `appName`.

binding-triggered:: Fired when a keyboard binding is triggered. Includes `binding`, `mode`.

// =========================================================== Output Format
include::util/conditional-output-format-header.adoc[]

Events are output as JSON lines (one JSON object per line):

----
{"_event":"focused-monitor-changed","monitorId":1,"workspace":"M"}
{"_event":"focused-workspace-changed","prevWorkspace":"M","workspace":"M"}
{"_event":"mode-changed","mode":"main"}
{"_event":"focus-changed","windowId":28218,"workspace":"M"}
{"_event":"focus-changed","trigger":"macos-focus-sync via ax(kAXFocusedWindowChangedNotification)","windowId":31904,"workspace":"1"}
----

=== The trigger field

The three focus events carry a `trigger`: what made Airlock re-evaluate focus. It turns the event
stream into a causal trace, which is what you want when focus moves on its own and you need to know
who moved it. Values look like:

`macos-focus-sync via <trigger>`:: macOS moved the focus and Airlock synced it in — an app activated
itself, or the user clicked. The qualifier after `via` is only which session noticed. This is what
focus stealing looks like from the outside.
`hotkey-binding`:: A keybinding from the config.
`socket-server(focus)`:: A CLI command; the name in parentheses is the command.
`global-observer(NSWorkspaceDidActivateApplicationNotification)`:: A macOS notification; the name in parentheses is the notification.
`ax(kAXFocusedWindowChangedNotification)`:: An accessibility notification from an app.
`global-observer-left-mouse-up`:: A mouse click.
`startup`, `config-auto-reload`, `menu-bar-button`, `reset-manipulated-with-mouse`:: Self-explanatory.
`on-window-detected`, `on-focus-changed`, `on-focused-monitor-changed`, `on-mode-changed`:: A callback from the config, which
means the change was caused by an earlier change. Repeating pairs of these are the signature of a
feedback loop.

The field is absent on the initial state sent on connect, since nothing triggered it.
